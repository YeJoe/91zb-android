## 七、结论演进（哪些旧结论已被推翻）

看旧文档前先对照这张表。**每一行都是踩过的坑**。

| 旧结论 | 现状 |
|---|---|
| `/room/list {"menu_id":104}` 能拉分类列表 | ❌ 8.5.3 已下线：17 个端口全 404，源 App 冷启动全程不调用 |
| `/room/get_info_by_ids` 拿详情 | ❌ 正确名字是 `/room/get_list_by_ids`，`ids` 是逗号串不是数组 |
| 房间列表只能读 JSON 快照（公网 403） | ⚠️ 公网确实不通，但本机隧道能通；App 默认实时，JSON 只做降级 |
| `on_air` 有区分力，可以拿来筛 | ❌ 2248 间里只有 39 间是 0，等于没筛 |
| `player_count` 可以筛在播 | ❌ 下播后不清零，纯残留值 |
| `on_air` / `live_in` 都不能判在播 | ⚠️ 半对：`live_in` 是唯一会翻转的布尔（662/2230 为 0），但接口里 600 条样本只有 5 条为 0，**只能软筛**；真判据是 FLV 头 |
| 靠 **全量**探活筛掉死房 | ❌ 1972 间跑一轮 = 8 分钟/小时射频满载。改成可见窗口 + 40 预取 + 20 分钟 TTL，< 1 分钟/小时 |
| 探活不通就**删房间** | ❌ 列表会在手指底下变短，也是「刷新后 0 房间」的成因。改成置顶/沉底/压暗 |
| 弹幕端口是固定的，缓一次能长期用 | ❌ 每次冷启动重排（`11689` → `34199` → `37679`） |
| 明文 `POST /websock/history_msg` 回 405 是判据 | ⚠️ PC 上有效，手机上筛不出；改成 **`POST /websock/join` 回 405** |
| `POST /websock/join` 回 200..299 才算命中 | ❌ 真端口回 405，这条把真端口判死，命中列表永远为空 |
| 端口回 403 且 body 是 JSON 就算命中 | ❌ 403 是别的业务 vhost 的鉴权层（`设备登陆中`），路由不认 `/websock` |
| 弹幕只能放离线样本 | ❌ 已接实时 WS：join 后只收 `room_msg` 推送，20 秒 130 条 |
| 源 App 必须同机常驻 | ❌ 已把 `libkiwi.so` 打进自己 APK，App 自己 `Init`、自己开 listener |
| 按 Home 自动缩成小窗 | ❌ 已改为**只有**播放页顶栏「浮窗」手动进 |
| 小窗里再画一层整屏封面/手势层没问题 | ❌ 模拟器上应用层合成排在 `PipMenuView` 之上，会盖住系统的全屏键和设置齿轮 |
| 进房用 `/room_push/join` | ❌ 8.5.3 是 `/websock/join`；`-5003` 就是路径过期的表现 |
| 分类参数是 `menuId` | ❌ 必须是 `menu_id`（下划线），写错服务端静默返回默认列表 |
| 靠拉流判断是不是真人直播间 | ❌ 拉流测的是「此刻有无推流」，下播的真人房会被误杀；分类看 `menu_id` |
| API 有真实域名，被加固隐藏 | ❌ BASE 是 `127.0.0.1` 本地隧道（现在由我们自己的进程提供） |
| 需要破解 libkiwi.so 才能解密 | ❌ 加密在 Dart 层，且明文分支可用 |
| 用 Frida 动态 dump 密钥 | ❌ arm64 App 跑在 x86 容器的 Houdini 翻译层，gadget 挂不上 |
| 设置页开关点了「不生效」是设置项问题 | ❌ 是 Compose 重组问题：UI 直接读 `prefs` 普通 getter，写盘不触发重组 |
| 关注列表和弹幕要同一套凭证 | ❌ 三件事三套凭证：列表零凭证、关注只认 JWE、弹幕要**会话 token + JWE**；详见 [凭证与换号.md](凭证与换号.md) |
| 会话 token 没有接口必须带，不用管 | ❌ `/websock/join` 必须带；缺了必回 `403 -10000 bad token, please login!`，且随源 App 冷启动变化 |

## 九、硬前提（命令行脚本形态）

用 `tools/` 里的脚本（而不是 App）时，这三条绕不开：

1. 隧道 URL 的 `?token=` 必须是**当前会话**的 32 位 hex，只能从 `lo` 回环明文抓（要冷启动）；
2. 请求要带 `authorization: Bearer <JWE>`（App prefs 里 330 字符那个）；
3. 端口必须是能跑 `/index/hello` **且**挂 `/websock/*` 的那台 vhost。

> 端口每次重启都会变。`/index/hello` 回 200 的端口有好几个，不能拿它当判据。
>
> **接口侧判据**：拿真实房间号打 `POST /room/get_list_by_ids`，响应带 `rooms` 键的才是对的 vhost。
> **不能用 `/room/list` 探**——已下线，所有端口 404，会把正确端口也筛掉。
>
> **通道侧判据**：明文 `POST /websock/join` 回 **405** 的才是 IM vhost（403 是别的 vhost 的鉴权层）。

> App 里这三条都由内置 SDK 自己解决，用户不需要关心。
