## 三、结论演进（哪些旧结论已被推翻）

看旧文档前先对照这张表，避免被误导。

| 旧结论 | 出处 | 现状 |
|---|---|---|
| `/room/list {"menu_id":104}` 能拉分类房间列表 | `真人直播间筛选.md`、`成功总结.md`、早期 README | ❌ **8.5.3 已下线**：17 个本地端口全 404，源 App 冷启动全程不调用 |
| `/room/get_info_by_ids` 拿房间详情 | `直播接口清单.md` §1 | ❌ 正确名字是 **`/room/get_list_by_ids`**，`ids` 是逗号串不是数组 |
| 房间列表只能读 JSON 快照（接口公网 403） | `安卓App设计方案.md` §1 | ⚠️ 公网确实不通，但**本机隧道能通**；App 现在默认实时模式，JSON 只做降级 |

| `/room/list` 必须带 JWE 否则报「查询类型错误」 | `明文接口突破.md`、`直播接口清单.md` | ❌ 那是接口还活着时的行为，现在直接 404，轮不到鉴权 |
| 进房用 `/room_push/join` | 早期笔记 | ❌ 8.5.3 是 **`/websock/join`**；`-5003` 就是路径过期的表现 |

| 靠拉流判断是不是真人直播间 | `tools/probe_stream.py` | ❌ 拉流测的是「此刻有无推流」，下播真人房会被误杀 |

## 五、三个硬前提（任何接口调用都绕不开）

1. 隧道 URL 的 `?token=` 必须是 **App 当前会话的 32 位 hex**（只能抓 `lo` 回环明文获得）；
2. 必须带 `authorization: Bearer <JWE>`（App prefs 里 330 字符那个）；
3. 端口必须是同时能跑 `/index/hello` 和 `/websock/*` 的那台 vhost。

> 端口每次重启都会变（实测 `38481 → 45209 → 33297 → 38103 → 36909`），`/index/hello` 回 200 的端口有好几个，
> 不能拿它当判据。
>
> **接口侧**的判据：拿一个**真实房间号**打 `POST /room/get_list_by_ids`，响应里带 `rooms` 键的才是对的 vhost。
> **不能用 `/room/list` 探**——它已经下线，所有端口都回 404，会把正确的端口也筛掉。
> 空 `ids` 的探针也不行：回的是 `{"code":-1,"msg":"ids is null"}`，**不带 `rooms` 键**，一样认不出来。
>
> **通道侧**的判据：明文 `POST /websock/history_msg` 只有业务 vhost 回 405（其余 403/404），
> 再用一次 `history_msg` 拿到 200 才算选中。`tools/live_ws.py` 的 `connect(probe_rid=…)` 已按这个实现。

具体拿法见 [攻坚全记录.md](攻坚全记录.md) 阶段五。
