# Android 直播 App 弹窗禁用修改教程（v4.3.3 混淆版 / 版本无关）

> 本文档基于 `libapp.so` 4.3.3 实测。所有定位方式均采用**版本无关的 ARM64 字节特征码**——地址会变，特征码不会变。换版本后只需重新搜索即可定位，无需依赖 IDA 符号名。

---

## 零、核心原则：版本更新后如何重新定位

**地址会变，特征码不变。** 原因：Dart VM 的 AOT 编译器只对符号名做随机化混淆（函数名从 `_needPay` 变成 `sub_8BF634`），但**指令序列、数据流结构、门控逻辑完全不动**。

本教程涉及的 4 处修改点，全部提供：
1. **唯一特征码**（Alt+B 直接搜索命中，或命中少量候选后人工确认）
2. **版本无关的候选筛选规则**（如何从多个命中中选对目标）
3. **上下文验证方法**（xref / 调用链确认没改错）

**修改前务必先搜索特征码确认位置，不要直接复制地址到十六进制编辑器。**

---

## 一、重要前提

1. **IDA 地址 = 文件偏移**
   - 本 `libapp.so` 所有 `LOAD` 段满足 `vaddr − file_offset = 0`。
   - IDA 中看到的地址可直接当作十六进制编辑器偏移使用。
   - 如果新版本的 SO 不满足此条件，请用 IDA 的 `Edit → Segments → Rebase program` 或十六进制编辑器自行计算偏移。

2. **ARM64 小端字节序**
   - `ADD X1, X1, X28, LSL#32` = `21 70 10 8B`
   - `CMP W1, #2` = `3F 08 00 71`
   - `CMP W1, #4` = `3F 10 00 71`
   - `STP X29, X30, [X15,#-0x10]!` = `FD 79 BF A9`
   - `RET` = `C0 03 5F D6`
   - `NOP` = `1F 20 03 D5`

3. **修改策略只有三种字节操作**
   - **改分支条件码**：`B.NE` → `B`（无条件跳过），只改 1 字节条件码
   - **NOP 掉调用**：`BL target` → `NOP`，4 字节覆盖
   - **整函数 RET**：`STP X29,X30,[X15,#-0x10]!` → `RET`，4 字节覆盖

---

## 二、修改点总览

| # | 弹窗类型 | 触发场景 | 修改方式 | 特征码搜索 |
|---|---------|---------|---------|-----------|
| 1 | 直播间付费弹窗 (payType==2) | 进入付费直播间 | 改 `B.NE` → `B` | `21 70 10 8B 3F 08 00 71` |
| 2 | 直播间预览弹窗 (preview==4) | 预览模式超时 | 改 `B.NE` → `B` | `3F 10 00 71` + 下方找 `BL sub_8BF634` |
| 3 | 首充图片弹框 | 进直播间 ~20s 后 | 整函数 RET | xref 确认 + 首指令改 RET |
| 4 | 首页广告弹框 | 启动进入 HomePage | 整函数 RET | `FD 03 0F AA EF E1 01 D1 A1 83 1B F8` |

**四处都改才能彻底清静。**

## 三、修改点 1：直播间付费弹窗 (payType == 2)

### 3.1 定位特征码（版本无关）

在 IDA 中按 `Alt+B`，搜索字节序列：

```
21 70 10 8B 3F 08 00 71
```

- `21 70 10 8B` = `ADD X1, X1, X28, LSL#32` —— Dart AOT 的数据流解压特征，极少数函数会用到这个特定模式
- `3F 08 00 71` = `CMP W1, #2`

该组合具有极高的唯一性，通常**一次命中**。如果命中了多个，向下找紧跟着 `B.NE`（`A1 ?? ?? 54`）+ `BL` 的那个。

### 3.2 目标代码结构

```asm
; 特征码起点
ADD   X1, X1, X28, LSL#32     ; 21 70 10 8B
CMP   W1, #2                  ; 3F 08 00 71
B.NE  loc_xxxx                ; A1 ?? ?? 54   <== 改这里
; —— 以下只在 W1==2 时执行 ——
LDUR  X0, [X29,#-0x58]
LDUR  W1, [X0,#0xF]
ADD   X1, X1, X28, LSL#32     ; 21 70 10 8B
BL    sub_xxxx                 ; == _needPay    <== 或 NOP 这里
B     loc_xxxx
```

语义：`W1 == 2`（payType==2）时执行付费弹窗；`B.NE` 在 `W1 != 2` 时跳过。

### 3.3 修改方案

**方案 A（推荐，改分支为无条件跳过）：**
- 目标：`B.NE` 所在地址（即特征码命中地址 + 8）
- 原字节：`A1 ?? ?? 54` → 新字节：`AE ?? ?? 54`
- 原理：`A1` 是 `B.NE` 的条件码，改成 `AE` 变成 `B.AL`（无条件分支），只改 1 字节，不依赖偏移计算
- 效果：无论 payType 是否等于 2，都跳过 `_needPay`

**方案 B（NOP 掉调用指令）：**
- 目标：`BL sub_xxxx`（`_needPay`）所在地址
- 原字节：4 字节 `BL` 指令 → 新字节：`1F 20 03 D5`（NOP）
- 效果：即使进入付费分支也不调用弹窗函数

> v4.3.3 实测：特征码命中 `0x1049D2C`，`B.NE` 在 `0x1049D34`，`BL` 在 `0x1049D44`。

## 四、修改点 2：预览状态付费弹窗 (preview == 4)

`_needPay` 被调用 **2 次**（payType==2 一次、预览超时一次）。第二处的门控是 `CMP W1, #4`。

### 4.1 定位特征码（版本无关）

**方法 A（推荐，xref 反查）：**
1. 先在 IDA 中找到 `_needPay` 函数（通过修改点 1 的 `BL target` 进入）
2. 光标移到该函数，按 `Ctrl+X` 看交叉引用
3. 会列出 2 个调用者：第一个是修改点 1，**第二个**就是预览门控
4. 进入第二个调用者，找到 `CMP W1, #4` + `B.NE` + `BL _needPay`

**方法 B（字节搜索 + 人工确认）：**
1. `Alt+B` 搜索 `3F 10 00 71`（`CMP W1, #4`）
2. 在命中的函数中向下找 `BL _needPay`（地址与修改点 1 中 `BL` 的目标相同）
3. `BL` 上方就是 `B.NE`，这就是要改的分支

### 4.2 修改方案

与修改点 1 完全一致：
- 改 `B.NE` → `B.AL`（条件码 `A1` → `AE`），或
- NOP 掉对应的 `BL _needPay`（`1F 20 03 D5`）

> v4.3.3 实测：第二处门控 `CMP W1, #4` 在 `0x8BF5CC`，`B.NE` 在 `0x8BF5D0`，`BL _needPay` 在 `0x8BF614`。

## 五、修改点 3：首充图片弹框 (showFirstRechargeDialog)

进入直播间约 20 秒后会弹出"首充大礼包"图片弹框。这是**独立函数**，与前两处门控不同。

### 5.1 定位特征码（版本无关）

**特征码搜索法（版本无关，推荐）：**

此弹框函数的核心特征是：**它是一个独立的 Dart 函数，被直播间页面闭包唯一调用，函数体开头有特征性的 `SUB X15, X15, #0x40`**。

1. 在 IDA 中 `Alt+B` 搜索：
   ```
   FD 79 BF A9 FD 03 00 91 F1 03 00 D1 A1 83 01 F8
   ```
   这条序列 = `STP X29,X30,[X15,#-0x10]!` + `MOV X29, X15` + `SUB X15, X15, #0x40` + `STUR X1, [X29,#-8]`

2. 这会命中多个 Dart 函数头。需要进一步筛选：每个命中处，看其内部是否有：
   - `LDR X0, [X26,#0x68]` 紧接着 `LDR X0, [X0,#0x27D0]`
   - 调用 `BL AllocateyTaStub_xxxxxxxx`（`AllocateyTaStub` 是首充弹框的专用 allocator）

3. 满足以上两个条件且**被直播间页面闭包调用**的，就是目标函数。

**xref 法（需要先找到直播间页面闭包）：**
1. 搜索字符串 `showFirstRechargeDialog` 或 `first_recharge` 的 xref
2. 如果字符串也被混淆，找 `AllocateyTaStub` 的调用者
3. 确认其唯一调用方是直播间页面闭包

> v4.3.3 实测地址：`0xF26DC0`。身份确认：仅被 `EZo__vVa___anon_closure_f26c90` 调用。

### 5.2 修改方案（整函数 RET 掉）

- 目标：函数首条指令 `STP X29, X30, [X15,#-0x10]!` → `RET`
- 原字节：`FD 79 BF A9` → 新字节：`C0 03 5F D6`
- 效果：函数一进入就返回，弹框逻辑整体跳过

## 六、修改点 4：首页广告弹框 (HomePage 启动广告)

启动 App 进入 HomePage 时弹出的广告弹框（疑似 WebView）。这是**独立函数**，由 HomePage 初始化流程调用。

### 6.1 为什么改这里有效 —— 身份确认证据链

**IDA 调用链（v4.3.3，地址会变但结构不变）：**
```
sub_FF6D90                        ← 广告弹框展示函数
  ↑ BL 调用
sub_5E9974                        ← 创建 zTa 对象后立即调广告弹框
  ↑ BL 调用
sub_5E986C                        ← zTa 构造闭包
  ↑ BL 调用
sub_5E9804                        ← 路由分发入口
  ↑ BL 调用
sub_5D625C                        ← 通用跳板（被 38 处引用）
```

**pp.txt 对象池交叉验证：**
- `sub_5E9974` 紧邻 `AnonymousClosure: (0x5e99ec), of [TSo] zTa`（差值 = 函数大小）
- `zTa` 所属页面内嵌字符串 `"HomePage"` 和 `"_needShowStepDialogWhenHomePageReVisible"`
- `_CVa` 类（`pUo.dart`）就是混淆后的 **HomePage State 类**
- `sub_5E986C` 被 `pUo__CVa::_anon_closure_5e9c4c` / `_5e9c9c` 调用 —— 即 HomePage 可见时触发

**结论**：该函数是 HomePage 初始化时调用的广告弹框。版本更新后，函数地址会变，但**调用链结构不变**。

### 6.2 定位特征码（版本无关）

在 IDA 中按 `Alt+B`，搜索字节序列：

```
FD 03 0F AA EF E1 01 D1 A1 83 1B F8
```

- `FD 03 0F AA` = `MOV X29, X15`（Dart 函数 prologue 第 2 条指令）
- `EF E1 01 D1` = `SUB X15, X15, #0x78`（栈帧大小 0x78，该值是这个函数的独特特征）
- `A1 83 1B F8` = `STUR X1, [X29,#-0x48]`

该序列在多个 Dart 函数中都会出现（所有栈帧为 0x78 的函数）。命中后需要**进一步筛选**：

**筛选规则（版本无关）：**
1. 命中结果中**取第 2 个**（经验规则，v4.3.3 实测命中 3 个，第 2 个是目标）
2. 或：每个命中处检查函数内部是否有 `BL AllocateContextStub_xxxxxxxx` → `MOV X3, X0` → `LDUR X0, [X29,#-0x48]` → `STUR X3, [X29,#-0x58]` → `STUR W0, [X3,#0xF]` 这个特征序列
3. 或：通过调用链反查 —— 如果该函数被 `sub_5E9974`（或等效函数）调用，且 `sub_5E9974` 内调用了 `AllocatezTaStub_xxxxxxxx`，则确认身份

> v4.3.3 实测地址：`0xFF6D90`。身份确认：被 `sub_5E9974`（zTa 初始化闭包）在 `+0x5C` 处 `BL` 调用。

### 6.3 目标代码

```asm
.text:xxxxxxxxxxxxxx sub_xxxx      ; CODE XREF: sub_5E9974+5C↑p
.text:xxxxxxxxxxxxxx STP X29, X30, [X15,#-0x10]!  ; <== 改这里为 RET
.text:xxxxxxxxxxxxxx MOV X29, X15
.text:xxxxxxxxxxxxxx SUB X15, X15, #0x78
.text:xxxxxxxxxxxxxx STUR X1, [X29,#-0x48]
.text:xxxxxxxxxxxxxx LDR X16, [X26,#0x38]
.text:xxxxxxxxxxxxxx CMP X15, X16
.text:xxxxxxxxxxxxxx B.LS loc_xxxx
.text:xxxxxxxxxxxxxx MOV X1, #1
.text:xxxxxxxxxxxxxx BL  AllocateContextStub_xxxxxxxx
...
```

### 6.4 修改方案（整函数 RET 掉）

- 目标：函数首条指令 `STP X29, X30, [X15,#-0x10]!` → `RET`
- 原字节：`FD 79 BF A9` → 新字节：`C0 03 5F D6`
- 效果：函数一进入就返回，广告弹框逻辑整体跳过，不影响 HomePage 其他初始化

## 七、版本更新后的通用定位流程

每次拿到新版本的 `libapp.so`，按以下步骤操作：

### Step 1：打开 SO，确认 vaddr == file_offset

在 IDA 中加载 `libapp.so`，等待自动分析完成。检查第一个 `LOAD` 段的 `vaddr` 是否等于 `file_offset`。如果不等，记下偏移量，后续十六进制编辑时需自行换算。

### Step 2：定位修改点 1（付费弹窗 payType==2）

```
Alt+B → 搜索: 21 70 10 8B 3F 08 00 71
```

通常一次命中。记录 `CMP W1, #2` 下一条 `B.NE` 的地址（= 命中地址 + 8）。

### Step 3：定位修改点 2（预览弹窗 preview==4）

从修改点 1 的 `BL target` 进入 `_needPay` 函数 → `Ctrl+X` 看 xref → 进入第二个调用者 → 找 `CMP W1, #4` 后的 `B.NE`。

或者直接搜 `3F 10 00 71`，在命中中找包含 `BL _needPay`（地址与 Step 2 中找到的一致）的那个。

### Step 4：定位修改点 3（首充图片弹框）

搜 `FD 79 BF A9 FD 03 00 91 F1 03 00 D1 A1 83 01 F8`，对每个命中检查函数内部是否有 `LDR X0, [X0,#0x27D0]` + `BL AllocateyTaStub_xxxxxxxx`。

**辅助判断**：如果新版 `pp.txt` 可用，搜 `img_first_recharge_dialog` 字符串的引用闭包，其内部 `BL` 调用的目标就是该函数。

### Step 5：定位修改点 4（首页广告弹框）

搜 `FD 03 0F AA EF E1 01 D1 A1 83 1B F8`，取第 2 个命中。验证函数内部有 `BL AllocateContextStub` + `STUR W0, [X3,#0xF]` 特征。

### Step 6：执行修改

```python
# 自动化修改脚本（填入 Step 2~5 定位到的实际地址）
so = r'libapp.so'
with open(so, 'r+b') as f:
    # 修改点 1：B.NE → B.AL（无条件跳过付费弹窗）
    f.seek(PAY_TYPE2_B_NE_ADDR)
    f.write(bytes.fromhex('AE000054'))  # 或根据偏移写入 B 指令

    # 修改点 2：B.NE → B.AL（无条件跳过预览弹窗）
    f.seek(PREVIEW_B_NE_ADDR)
    f.write(bytes.fromhex('AE000054'))

    # 修改点 3：首充图片弹框 RET
    f.seek(FIRST_RECHARGE_ADDR)
    f.write(bytes.fromhex('C0035FD6'))

    # 修改点 4：首页广告弹框 RET
    f.seek(HOME_AD_ADDR)
    f.write(bytes.fromhex('C0035FD6'))
```

## 八、特征码速查表

| 修改点 | 搜索特征码（小端 hex） | 对应指令 | 命中后操作 |
|--------|----------------------|---------|-----------|
| 付费弹窗 | `21 70 10 8B 3F 08 00 71` | `ADD X1,X1,X28,LSL#32` + `CMP W1,#2` | 下一条 `B.NE` 改 `B.AL` |
| 预览弹窗 | `3F 10 00 71` | `CMP W1,#4` | 配合 xref 确认后改 `B.NE` |
| 首充弹框 | `FD 79 BF A9 FD 03 00 91 F1 03 00 D1 A1 83 01 F8` | 函数头（栈帧 0x40） | 人工确认后首指令改 RET |
| 首页广告 | `FD 03 0F AA EF E1 01 D1 A1 83 1B F8` | `MOV X29,X15` + `SUB X15,#0x78` + `STUR X1,[X29,#-0x48]` | 取第 2 个命中，首指令改 RET |

| 修改操作 | 原字节 | 新字节 | 说明 |
|---------|--------|--------|------|
| `B.NE` → `B.AL` | `A1 ?? ?? 54` | `AE ?? ?? 54` | 只改条件码，无条件跳过 |

| `STP ...` → RET | `FD 79 BF A9` | `C0 03 5F D6` | 整函数直接返回 |

## 九、验证与注意事项

1. **修改前务必备份**原始 `libapp.so`。
2. 修改后建议用 Frida hook 对应函数，确认弹窗不再弹出且 App 不崩溃。
3. 若 App 有完整性校验（MD5/签名），可能需要额外绕过。
4. **版本更新后**：按 §七 流程重新搜索特征码定位，不要直接复制旧版地址。
5. 如果 Dart AOT 编译器大版本升级导致指令序列变化（罕见），需结合 `pp.txt` 对象池字符串交叉验证重新确认身份。
