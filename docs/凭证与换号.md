# 凭证与换号（三样能力，三套凭证）

> 定稿：2026-10-30 · 依据：设备上 46 个 LISTEN 端口逐个 `adb forward` 后打明文 POST 的实测结果
> 涉及接口：`/room/get_list_by_ids`、`/user_follow/my_follow`、`/websock/join`

一句话结论：**看列表不用任何凭证；关注只认 JWE；弹幕进房要「会话 token + JWE」，缺一个就是 403。**

---

## 一、结论表（三件事互不干扰）

| 能力 | 要什么 | 不要什么 |
|---|---|---|
| 看列表 `get_list_by_ids` | 什么都不用 | token、JWE 都不需要 |
| **关注列表** `my_follow` | **JWE**（内置那份就行） | **与会话 token 无关** |
| 弹幕进房 `/websock/join` | **会话 token + JWE** | —— |

这是实测出来的，不是从抓包里猜的。三条证据：

1. 业务 api vhost（23028 / 24121 / 34235 / 36645）上，`get_list_by_ids` 不带任何头就回
   `200 + rooms`；同一端口带不带 `?token=` 结果一模一样 —— 列表接口在鉴权层之前就被路由走了。
2. 同一端口 `my_follow` 什么都不带回 `{"code":-1,"msg":"请先登录"}`，
   **只**加 `authorization: Bearer <JWE>` 就回 15 位关注（`{}` 一次拿全，无分页）。
3. IM vhost（38105 / 43991 / 38897 / 51547）上，join 带 JWE 但缺 `?token=` 必回
   `403 {"code":-10000,"msg":"bad token, please login!"}`；把 32 位会话 token 补上立刻进房。

> ⚠️ 别把 405 当"端口对"的充分判据：`/websock/*` 在 nginx 上只接 WS 升级，
> 普通 GET/POST 回 405 只证明"这个端口挂着 /websocket 路由"，不证明你进得了房。
> 完整推导见 [弹幕404根因与修复.md](弹幕404根因与修复.md) §九。

## 二、三套凭证分别是什么

### 2.1 会话 token（32 位 hex）

- 长相：`e24bae48feeb58fc402e3ffd57e97d70`（示例，2026-10-30 实测可用，源 App 重启后已失效）
- 用途：拼在 `/websock/join?token=…` 上，是 join 的**唯一身份**
- 来源：源 App 当前会话。导出工具（`tools/token_export.py`）输出里的「【会话 Token】」那一行
- 寿命：**短**。源 App 每次冷启动都会换，App 里表现为"昨天能进房、今天 403"

### 2.2 JWE（330 字符）

- 长相：五段用 `.` 分隔，第一段是 `{"alg":"dir","enc":"A128CBC-HS256"}` 的 base64，第二段为空
  （`dir` 模式没有 encrypted_key），后面依次是 iv / 密文 / tag
- 用途：`authorization: Bearer <JWE>`。**关注列表的唯一凭证**，弹幕 join 也要它
- 来源：源 App 的 `FlutterSharedPreferences.xml` → `flutter.MAINUSER_DATA` → `token` 字段，
  原样取出。导出工具会打印「【JWE】」那一段
- 寿命：**长**。它不是会话令牌，不随登录刷新，实测两天内没变、也没观察到过期
- App 里已内置一份当默认值（`Prefs.Defaults.JWE`），装完即用不用填

### 2.3 看列表：什么都不用

`get_list_by_ids` 是唯一真正"裸奔"的业务接口。App 靠它拿房间数据，
所以**凭证全错也不影响首页**——这也是为什么"列表正常、关注空、弹幕 403"能同时出现。

## 四、换账号怎么做

换号要动的是**同一个账号下的两样东西**，而且只换一样会得到"半个账号"的怪状态：

| 只换 JWE | 只换会话 token |
|---|---|
| 关注列表变新号 ✅、弹幕仍 403 ❌（token 还是旧会话） | 弹幕可能进房 ✅、关注还是旧号 ❌（JWE 没换） |

步骤：

1. 源 App 里退出登录 → 登入新号；
2. 在新号状态下跑一次导出工具，拿到**新的【JWE】**和**新的【会话 Token】**；
3. TM Live → 设置 → **直播源与隧道** → JWE 输入框粘贴新 JWE
   （框下方「当前生效 JWE」可展开对照，粘完再比一次）；
4. 设置 → **弹幕** → 会话 token 输入框粘贴新的 32 位 hex → 点「保存并重连」；
5. 回首页下拉刷新：卡片数量应与新号在播关注数一致；进任意直播间看状态行是否 `已进房 :端口`。

> 一步到位的替代路径：把导出工具的整段输出丢进「导入配置（从导出工具粘贴）」，
> 它同时认 `【JWE】`/`【会话 Token】`/`【隧道端口】`，也会顺手重启弹幕。

**换号后没生效的自查顺序**（按命中率排）：

1. token 是不是复制时带了换行/空格（必须正好 32 位 hex）；
2. JWE 是不是还停在旧号（展开「当前生效 JWE」比对尾 12 位）；
3. 源 App 是不是又冷启动了（token 会变）；
4. 端口是不是换了（隧道端口每次启动都变，留空让它自己扫）。

## 五、失效现象对照表

| 现象 | 直接原因 | 动作 |
|---|---|---|
| 首页有房间，关注页空 | JWE 失效 / 是别的号的 | 重新导出 JWE，粘到设置页 |
| `my_follow` 回 `{"code":-1,"msg":"请先登录"}` | 没带或带错 JWE | 同上 |
| 弹幕状态行 `join 回403 · bad token` | 缺会话 token / token 过期 | 重新导出【会话 Token】 |
| 弹幕状态行 `缺会话 token：…` | `prefs.appToken` 为空，App 主动快速失败 | 同上（这版新加的提示） |
| 弹幕一直 404 | 端口不对（业务 vhost 没有 `/websock`） | 设置页「诊断端口」，命中会自动写回 |
| 弹幕一直 405 | 打到了 IM vhost 的非升级请求 | 正常现象，换端口继续试 |
| 端口探测一轮要很久 | 候选表被失败结果毒化 | 现在失败也记原因、成功集随端口表失效，重连即可 |

## 六、App 里在哪看、在哪改

| 位置 | 能干什么 |
|---|---|
| 设置 → 直播源与隧道 → `JWE（关注 / 弹幕用，已内置默认）` | 粘贴新 JWE；清空则回内置默认 |
| 设置 → 直播源与隧道 → **当前生效 JWE · 330 字符** | 折叠显示头尾，「展开全文」看全串，「复制」进剪贴板 |
| 设置 → 弹幕 → `会话 token（32 位 hex）` | 粘贴新 token，「保存并重连」会立即重连+轮询端口 |
| 设置 → 弹幕 → **当前生效会话 token · 32 字符** | 展开/复制，换号前先抄走留档 |
| 设置 → 关注 | 当前用的是「内置默认 JWE」还是「自定义 N 字符」 |

打开设置页看一眼就够判断："关注空 + 自定义 JWE" = 你换号时只换了一半。
