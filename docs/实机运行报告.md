# 实机运行报告：天美系 App 的 BASE / TOKEN 到底是什么

> 执行时间：2026-10-28 22:14–22:22
> 环境：MuMu 15.0（Android 15，x86_64，Magisk/KernelSU 已 root），
> 设备 `127.0.0.1:16384`，仅安装渠道包 `com.l95c2450d7.f68bb4e2d5`（8.5.3）。
> 结论部分**全部为本次实测**，不是推断；每条都标了取证方式。

---

## 0. 三条结论（先看这个）

| 问题 | 实测结论 |
|---|---|
| **BASE 是什么** | 不是域名，是 `http://127.0.0.1:<每次请求随机端口>`。App 把 HTTP 发给本机端口，由 `libkiwi.so`（云层隧道 SDK，`KiwiSDK version A521`）加密后经 `121.204.228.227:7001` 转发到真实后端。**真实域名在整条链路上从未以明文出现**。 |
| **TOKEN 是什么** | 就是 prefs 里 `MAINUSER_DATA.token` 那串 JWE，**原样**塞进 `Authorization: Bearer`。客户端不解密、不重签（已在报文里看到原值）。 |
| **能不能脱离 App 用** | **能，但必须借它的隧道端口**：`adb forward` 之后 PC 可以直连该端口并拿到后端响应（实测得到 Go 后端的 404/500）。已不需要真实域名。 |

---

## 1. 取证链路

### 1.1 设备侧：只有隧道，没有域名

```
adb shell su -c "cat /proc/net/tcp"          → net_tcp.txt
```

App 进程（uid 10061）的对外连接只有两类：

| 远端 | 性质 |
|---|---|
| `121.204.228.227:7001` | **kiwi 隧道入口**（明文 TCP，非 TLS） |
| `18.245.78.x:80` | CloudFront，图片 CDN（与 API 无关） |
| `115.236.122.147:443` | 证书反查 = `mumu.nie.netease.com`，是 MuMu 自己，不是 App |

对 `7001` 抓包（`tcpdump -i any port 7001`）后 payload 是**纯随机字节**，没有 `POST/GET/Host` 任何 HTTP 特征 → 隧道内是加密协议，域名不可见。

### 1.2 关键突破口：抓 loopback

```
adb shell su -c "tcpdump -i lo -s 0 -w /data/local/tmp/lo.pcap tcp"
```

App 发给本机端口的请求是**明文 HTTP**，完整报文见 `lo_dump.txt`：

```http
GET /go/rVC3YFXZjFxA4DH10hbA8nnRJS3PLpM5irJt07ZosI0=?z=1&nobase64=1&e=1 HTTP/1.1
user-agent: Dart/3.10 (dart:io)
host: 127.0.0.1:35981
authorization: Bearer <JWE>
cipher: NmX9KUnwUns=
```

信息量极大：

1. `host: 127.0.0.1:35981` → **BASE 的真实形态是 loopback 端口**；
2. `authorization: Bearer <JWE>` → token 就是 prefs 里那串，**不用解密**；
3. `pathPrefix = /go`，路径是 base64 串，且**带 `?z=1&nobase64=1&e=1` 三个参数**（文档里之前没有这三个参数）；
4. `Server: nginx/1.18.0 (Ubuntu)` 与 Go 后端的安全头，证明响应确实来自真实后端。

### 1.3 隧道端口可被外部复用 ✅

```
adb forward tcp:37217 tcp:37217
curl -i http://127.0.0.1:37217/go/          → HTTP/1.1 404（Go 后端返回）
```

再用标准库 `http.client` 直接 POST，也能拿到后端响应。**说明传输层已经完全打通，不再需要域名。**

## 2. 打到后端后，服务端"教"了我们三件事

用自己构造的加密请求（`rabbit.py`）打隧道端口，服务端逐层报错，等于把校验规则说了一遍：

| 我们发的 | 服务端响应 | 含义 |
|---|---|---|
| 路径用 base64url 且去填充（`rabbit.build_encrypted_path` 现状） | `500 illegal base64 data at input byte 28` | 填充不能去，长度必须是 4 的倍数 |
| 路径用标准 base64（含 `+`/`/`） | `500 illegal base64 data at input byte 1` | `+` 被当成空格，必须用 **urlsafe** 字母表 |
| urlsafe + 保留 `=`，明文路径 `/room/list`（10 字符） | `500 encrypted api path too short: 23 bytes` | 阈值是 **24 字节**，即路径明文 ≥ 11 字符（+13 字节 R2） |
| 同上，`/room/get_info_by_ids` 等 145 个已知接口 | `404`（空 body） | 长度过了，但**路由没命中** |

**结论**：
- 路径载荷格式 = `urlsafe_b64( 混淆(apiPath) + R2 )`，**保留 `=`**；`rabbit.py` 现在的 `.rstrip("=")` 是错的，必须改。
- 8.5.3 的**路径混淆算法与 8.1.7 不同**：拿抓到的 32 字节 blob 反推，按 8.1.7 的
  `reverse(xor(reverse(xor(path,R1)),R2)) + R2` 结构解不出任何可打印路径（穷举了 4 种分割 × 2 种翻转 ×
  11/13 周期，全部无解）。145 个已知接口全 404 也印证了这点。
- 因此 **SALT / RabbitCipher 是否 8.5.3 仍一致，目前无法验证**（要等一个能命中的路由才能看到密文响应）。

## 3. 与 8.1.7 逆向结论的差异（重要）

| 项 | 8.1.7（本文档目录里的分析） | 8.5.3（本次实测） |
|---|---|---|
| BASE | 假设为 `https://api.xxx.com` | **实为 `http://127.0.0.1:<port>` 隧道** |
| 真实域名 | 假设存在、可抓 | **不存在于任何明文流量中**，只在 kiwi 隧道内 |
| 路径编码 | `base64Url(...)` 去填充 | `urlsafe_b64` **保留填充** |
| 路径混淆 | `reverse(xor(reverse(xor(path,R1)),R2))+R2` | **已变**，同法反推无解 |
| 请求参数 | 无 | 必带 `?z=1&nobase64=1&e=1` |
| token | 明文 JWT | **JWE 原样**当 Bearer |
| 主数据通道 | REST | **WebSocket**（`/websock/*`，冷启动只建 WS，不拉 REST） |

## 4. 下一步（按投入产出排序）

1. **对 `channel.apk` 跑 blutter**（文件已在工作区，89MB，`lib/arm64-v8a/libapp.so` 27MB）：
   ```bash
   blutter channel.apk out853
   ```
   然后在 `out853/asm` 里对比三个函数，一次性解决路径混淆 + SALT：
   - `HttpRequest::encryptApiPath`（路径混淆，8.1.7 是 `0x111d870`）
   - `HttpTunnelLive4::initCipher`（SALT + key 派生）
   - `RabbitCipher::encryptDecrypt`（确认还是不是 Rabbit 变体）
   本机没有 blutter（已确认 PATH 与常见目录都没有），需要在有 Dart SDK 的机器上跑一次。
2. 拿到新算法后，改 `tools/rabbit.py` 两处即可（`encrypt_api_path` 保留填充、`derive_key` 换 SALT），
   客户端就能直接打 `http://127.0.0.1:<port>`。
3. 若要拿**天美自己的** token：仍需 `/login/quick`，但请求也得走它的隧道 —— 所以天美必须先能跑起来
   （闪退原因见 `BASE与TOKEN获取方案.md` §5；本次确认渠道包在 Android 15 x86_64 上可跑，靠 MuMu 的 ARM 翻译，
   而它 `lib/` 里只有 `arm64-v8a` + `armeabi-v7a`，**没有 x86_64**）。
