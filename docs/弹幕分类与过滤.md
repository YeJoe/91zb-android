# 弹幕分类与广告过滤

> 采样：`tools/danmaku_probe.py`，真人分类（`menu_id` 5/101/102/103/104/105/108）下的 **31 个房间、462 条消息**，
> 每房拉 `/websock/history_msg` + 监听 3 秒实时推送，原始样本落 `assets/data/dm.jsonl`（不入库）。
> 采集期间 App 被系统回收过一次，采到第 31 个房间中断；样本量对结论足够，重跑可继续累加。
> 规则实现：`tools/danmaku_filter.py`（唯一规则源）、`site/dm_filter.js`（网页端手抄版）。

---

## 1. 一句话结论

**弹幕里只有 `typ=32`（和 `typ=4` 的 @提及）是观众在说话，其余全是平台、博彩、运营消息。**
实测真人房里可直接显示的内容不到一半，另一半是下注、结算、关注、开奖、下单和引流广告。

所以「过滤广告」这件事不需要 NLP，也不需要模型：**消息自带类型码，按码分流即可**，
关键词只用来兜住少数没有类型码的纯文本广播。

---

## 2. 判据从哪来

消息对象长这样（`/websock/history_msg` 与 `ctl=room_msg` 推送同构）：

```json
{
  "id": 25495396872,
  "user_id": 1654380872,
  "nickname": "只是冷の匆匆",
  "content_type": 1,
  "optcode": 32,
  "content": "{\"text\":\"我喜欢老头乐\",\"typ\":32}",
  "create_time": 1793210541
}
```

三个字段决定一切：

| 字段 | 取值 | 说明 |
|---|---|---|
| `content_type` | `1` / `8` | 大类：`1`=纯文本，`8`=结构化（JSON 里带自己的 `typ`） |
| `optcode` | 顶层 | 只有部分消息带；`content_type=8` 时经常是 `null` |
| `content.typ` | 内嵌 | **最可靠**，几乎每条 `content_type=8` 的消息都有 |

⚠️ 坑：`content_type=8` 的消息，顶层 `optcode` 常常是 `null`，真正类型码在内嵌 JSON 的 `typ` 里。
只读顶层字段会把下注/结算全判成"未知"。规则里取码顺序是
`content.typ → optcode → content.optcode`。

## 3. 类型码全表（实测）

| typ | content_type | 含义 | 样本 | 处置 |
|---|---|---|---|---|

| `4` | 1 | @提及 | `{"text":"@凯凯哎哎啊 哥","typ":4}` | **保留**（也是聊天） |
| `3` | 8 | 送礼物 | `{"item_id":5020,"count":1,"combos":1}` | 保留（可选关） |

| `20` | 8 | 结算 / 中奖 | `{"pay_amount":392,"cp_name":"百人牛牛"}` | 丢弃 |
| `23` | 8 | 开奖 | `{"pre_draw_code":[2,2,2],"memo":"6 小 双","cp_type":3}` | 丢弃 |

## 4. 实测分布

样本 **31 个真人房 / 462 条消息**（见文首采样说明），过滤前后的构成：

| 类别 | 条数 | 占比 |
|---|---|---|
| 聊天（`32`+`4`） | 218 | 47.2% |
| 下注 | 110 | 23.8% |
| 结算中奖 | 43 | 9.3% |
| 关注 | 40 | 8.7% |
| 商城/心愿单下单 | 20 | 4.3% |
| 引流广告（含伪装成聊天的） | 13 | 2.8% |
| 系统（心愿达成/待定 18） | 7 | 1.5% |
| 管理操作 | 5 | 1.1% |
| 礼物 | 4 | 0.9% |
| 开奖 | 2 | 0.4% |
| **可显示** | **222** | **48.1%** |
| **需过滤** | **240** | **51.9%** |

两个值得记的观察：

1. **博彩消息占比随房间"盘口化"程度剧烈波动**。纯聊天房几乎只有 `32`，一旦主播挂盘口，
   `19/20/23` 会瞬间淹掉聊天，最高的一间房里聊天只占 12%。
2. **`5`（关注）和 `33/34`（下单）是"看起来像聊天"的那一类**：它们有昵称、有动词、有宾语，
   肉眼很容易当成弹幕，但都不是观众发言。

## 5. 关键词兜底：为什么还需要

类型码能覆盖 99% 的消息，但有两类例外：

1. **纯文本系统广播**没有 `typ`（或 `typ` 是未知值）——早期抓到的
   `麻将牛牛财神提款 … 速来围观！` 就属于这种，它靠 `desc` 文本传播；
2. **伪装成聊天的引流文案**（`typ=32`，但内容是"送跑车解锁 22 部福利视频…"），
   类型码上它确实是聊天，只能从文本特征认出来。

于是规则分两层：

```
         ┌─ 有类型码 ─→ 按 TYP_KIND 定 kind ─→ kind ∈ {chat,gift} ? 保留 : 丢弃
消息 ────┤
         └─ 无/未知类型码 ─→ 关键词打分 ─→ 命中博彩/广告/系统词 ? 丢弃
                                          └ 否则按文本是否像聊天决定
```

关键词表（`danmaku_filter.py`）：

| 词表 | 用途 | 举例 |
|---|---|---|
| `BET_WORDS` | 博彩/盘口 | 下注、结算、开奖、百家乐、快三、七星、东方彩票、收入囊中 |
| `AD_WORDS` | 引流/站外拉人 | 速来围观、加微、QQ群、邀请码、下载APP、稳赚 |
| `SYS_WORDS` | 平台运营通知 | 完成了主播、本场心愿、升级为、排行榜 |
| `SPAM_PATTERNS` | 硬广告特征 | `http://`、`.com`、`+v` |
| `CHAT_AD_WORDS` | 伪装成聊天的引流 | 加私人、福利视频、解锁、一对一、包本人 |

### 5.1 关键取舍：真人聊天**不**做博彩词过滤

`typ=32` 的消息直接放行，只拦链接和联系方式。原因是观众自己会聊"这把下注多少"、
"刚才开奖多少"，用博彩词表筛 `32` 会把正常讨论全部误杀。
同理，`CHAT_AD_WORDS` 只在**长度 ≥ 25 字**时才判——否则 `一对一多久`、`几个福利视频`
这种观众追问也会被误伤（这两条在实测里确实出现过）。

伪装文案的判定规则收敛为三条：

- 长度 ≥ 110 字 → 刷屏；
- 长度 ≥ 60 字且含 2 个以上 `💖💞💦🌊👍🉑` 之类表情 → 长文+表情轰炸；
- 长度 ≥ 25 字且命中 `CHAT_AD_WORDS`。

## 6. 落地

### 6.1 Python 端（采集 / 生成）

```python
import danmaku_filter as f
r = f.classify(item)      # {'kind':'bet','typ':19,'verdict':'drop','reason':'类型码 19',...}
kept = f.filter_items(items, keep=('chat','gift'))   # 可再传 stats={} 累计各类计数
```

`tools/build_danmaku.py` 用它把 `assets/data/dm.jsonl` 压成 `site/dm_samples.js`：
聊天占多数，另掺少量各类系统消息，供页面"全部"模式对照。

### 6.2 网页端

`site/dm_filter.js` 导出 `window.DmFilter`：

```js
DmFilter.classify({typ: 19, content: {total_amount: 20}})   // -> {kind:'bet', keep:false, ...}
DmFilter.filter(window.DANMAKU, {keepKinds: {chat:1}})      // -> {kept:[...], stats:{...}, dropped:n}
```

聊天区右上角两个开关：

- **只看聊天**（默认）：只渲染 `kind ∈ {chat, gift}`；
- **全部**：全部渲染，非聊天内容带灰色标签（下注/结算/关注/开奖/下单/广告），
  鼠标悬停能看到判定原因。

页头那行 `样本 N 条：聊天 x · 已过滤 y 条（z%）` 就是 `window.DM_STATS`，用来一眼验证过滤比例是否正常。

## 8. 已知边界

- **没有类型码的纯文本广播**只能靠词表，词表会漏新文案；漏了就在 `danmaku_filter.py` 里加词，
  再同步 `site/dm_filter.js`（两边必须同时改，否则网页与脚本判定不一致）。
- **`typ=18` 语义未确认**，目前按系统消息丢弃；若后续发现它是点赞/分享之类的互动，需要改判。
- **昵称里的广告**（例如昵称直接叫"XX 娱乐城"）不会被过滤，因为消息体内的文本是干净的；
  要拦就得对昵称作同套词表判定，属于产品取舍，未默认开启。
- 采样只覆盖真人分类的房间；盘口房（`menu_id` 8000~8013）里博彩消息占比更高，但不影响规则本身。
