# 明文长连接通道（/tunnel/open）与 init 数据

> 这篇记录 8.5.3 里那条**不加密**的长连接通道，以及 `/login/init` 到底给什么。
> 关键结论：**BASE 从来不存在一个"真实域名"——所有地址都是 `http://kiwi_*` 占位符，
> 由 kiwi SDK 在运行时替换成 `127.0.0.1:<端口>`。** 这解释了为什么静态分析永远找不到 BASE。

---

## 1. 三类通道

冷启动抓包（`tcpdump -i lo -w boot.pcap`，18 秒，**无需任何手动点击**）得到三条 WebSocket：

| 通道 | URL 形态 | 载荷 | 用途 |
|---|---|---|---|
| 明文代理 | `/tunnel/open?z=1&appversion=20260226001&token=<32hex>` | **JSON 明文**；响应体 zlib | HTTP 代理 + 服务端推送 |
| 二进制隧道 | `/tunnel/<8位hex>?z=1&nobase64=1&token=<32hex>` | 密文 | 业务数据 |
| 业务通道 | `/go/<44字符blob>?z=1&nobase64=1&e=1` | 密文 | 需要 `cipher:` 头 |

握手都要 `authorization: Bearer <JWE>`。

### 1.1 明文通道的协议

上行（**纯 JSON，未压缩**）：

```json
{"body":{},"random":91,"method":"POST","uri":"/login/init"}
```

下行有两种：

```json
{"opt":"http","data":{"status":200,"random":91,"body":"{\"code\":0,...}"}}
{"opt":"u","ctl":"room","data":{"live_in":0,"id":1839030130}}
{"opt":"r","ctl":"config","data":"[{...}]"}
```

`opt:"http"` 是对上行的应答（按 `random` 配对），`opt:"u"/"r"` 是服务端主动推送。
`body` 是**被转义的 JSON 字符串**，要二次 `json.loads`。

### 1.2 为什么 `/login/init` 只能用长连接

普通 HTTP 打它得到：

```json
{"code":-2,"msg":"仅支持长连接"}
```

试过 19 种 query/header 变体（`long=1`、`type=long`、`z=1&nobase64=1`、`Upgrade: websocket`、
`Accept: text/event-stream`、GET …）**全部同样被拒**——判定在传输层，不在参数层。

走 `/tunnel/open` 就正常返回，整个启动数据一帧帧推下来：

```
ctl=user         用户完整档案（含 encrypt_status:1）
ctl=user_amount  钻石/积分
ctl=notice       公告与跑马灯
ctl=config       ← 两批，47 KB 配置
ctl=user_bag     背包
http             汇总响应 {"code":0,"user":{...},"user_id":...}
```

## 2. 最重要的发现：BASE 是占位符

`config` 里有这么一批键（`config_group` 全是「渠道专属配置」）：

| config_key | config_value |
|---|---|
| `activity_url` | `http://kiwi_hd` |
| `rank_url` | `http://kiwi_hd` |
| `game_url` | `http://kiwi_yx` |
| `tg_url` | `http://kiwi_yx` |
| `pay_url` | `http://kiwi_pay` |
| `kedan_url` | `http://kiwi_kd` |
| `file_rz_url` | `http://kiwi_rz` |
| `cdn_bobi_url` | `http://kiwi_bobi` |
| `strike_url` | `http://kiwi_jz` |
| `waiactivity_url` | `http://kiwi_whd` |
| `im_url` | `http://kiwi_im/tunnel/open?z=1` |
| `kiwi_starts` | `kiwi_,127.0.0.1` |

`kiwi_starts` 直接写明了规则：**以 `kiwi_` 开头的主机名由 SDK 替换成 `127.0.0.1`**，
后面的后缀（`hd`/`im`/`pay`…）决定路由到哪个 vhost。

所以：

- App 里**没有**任何真实 API 域名，`BASE = http://127.0.0.1:<port>` 是设计如此，不是加密结果；
- 想脱离设备自己跑客户端，卡点不在"找 BASE"，而在 **kiwi SDK 建立的隧道本身**；
- `im_url` 里的 `/tunnel/open?z=1` 印证了 IM 走的就是这条明文通道。

## 3. init 里**没有** RTMP 域名

把 42 KB 的 init 全量抓下来后按关键字检索：

| 关键字 | 命中 |
|---|---|
| `hebeisaixin` | **0** |
| `rtmp` | **0** |
| `pull` / `play_url` / `liveplay` | **0** |
| `pzhibo` / `jrbanquan` / `zbzs.tv` | 各 1–2（都在公告文本和 H5 地址里，与推拉流无关） |

出现的域名只有：`license.vod2.myqcloud.com`（播放器 license）、
`drdue73ptt7o.cloudfront.net`（易盾）、`es3srtnmu4ss1kg3.jrbanquan.com`、
`pzhibo.tv` / `zb01.tv` / `zb10.tv` / `zbzs.tv`（都是公告里的"永久下载地址"）。

**结论：拉流域名不出现在任何启动/配置数据里，只能在进房时的 RTMP 握手报文里读到。**
好消息是它**平台级固定**，抓一次可长期复用（详见 `docs/视频流拉取方案.md`）。

## 4. 房间能不能拉流：看 `chess_id`

`/room/get_list_by_ids` 返回的房间里：

| 房间 | menu_id | chess_id | 能否拉 RTMP |
|---|---|---|---|
| 琦琦77U / 小辣妈 / 大王来抓我呀 | 102/103 | **3** | ✅ |
| 常赢百家乐 / 马上暴富百家乐 / 赢钱百家乐 | 101/103 | **8** | ❌ |
| 梨子快三 | **8** | 3 | ❌ |

判定规则：**`chess_id == 3` 且 `menu_id >= 100`**。
`chess_id=8` 是百家乐/彩票桌，只有牌桌画面不走视频流；`menu_id=8` 是彩票频道。
实测按此规则从 50 个在线房间里筛出 26 个可拉流，抽检 4 个中 3 个直接出流
（分辨率有 720×1280 和 540×960 两种）。

## 10. libkiwi.so 静态分析（2026-10-29）

### 10.1 它在 APK 里

| 路径 | 大小 |
|---|---|
| `lib/arm64-v8a/libkiwi.so` | 6,858,488 |
| `lib/armeabi-v7a/libkiwi.so` | 5,573,052 |

已提取到 `libs/`。

### 10.2 可以用 IDA 分析，但它是加固的

两条路都验证过：

1. **IDA Pro 9.3 GUI**：`D:/Apps/IDA Pro 9.3\ida.exe`
2. **idalib（无 GUI）**：`pip install "<IDADIR>/idalib/python/idapro-0.0.7-py3-none-any.whl"`，
   设 `IDADIR=D:/Apps/IDA Pro 9.3`，之后 `import idapro; idapro.open_database(path, True)`。
   实测 `rc=0`，首次自动分析 16.9 s，复用数据库 3.9 s。

> `idat.exe -A -S` 批处理跑不通：用户的 `auto_re.py` / `symless` / `WPeChatGPT` 插件在无 GUI 下
> import PySide6 抛异常，把进程带崩。idalib 只报插件 ERROR 日志、不影响主流程，是正确用法。

**加固证据（idalib 报告 `tools/kiwi_report.txt`）：**

| 现象 | 实测 |
|---|---|
| 段名伪装 | 真 `.text` 只有 16 字节；代码塞进 `.note.gnu.proc`(2.1MB rx)、`.note.gnu.text`、`.note.gnu.content` |
| 导出符号 | 9467 个，全是乱码：`_____Y_____2__kf_______2___$__4&____…` |
| 字符串 | 21091 条可打印串里，仅 78 条"像单词"，且都是 `JZ1Azbao` / `WgtE\|9` 类随机串 |
| 有效字符串 | 仅 3 条：`libkiwi.so`、`signal`、`JNI_OnLoad` |
| 函数识别 | 只有 168 个；真逻辑在 `0x59xxxx` 的 24 个大函数（最大 3272 字节） |

结论：**能反汇编，读不出语义**。要走通必须动态（Houdini 下 Frida 不可用，见 §8）。

### 10.3 但加密根本不在 libkiwi 里

同一条隧道、同一个 libkiwi，三条通道的帧形态完全不同：

| 通道 | 帧特征 | 判定 |
|---|---|---|
| `/tunnel/open?z=1` | `78 9c` / `78 da` 开头 | **zlib 明文** |
| `/tunnel/a033b072?z=1&nobase64=1` | 高熵、非 16 倍数长度、无 zlib 头 | 密文 |
| `/go/<32字节base64>` | 同上 | 密文 |

若加密由 libkiwi 负责，`/tunnel/open` 不可能出明文。**故加密发生在上层（Dart AOT，libapp.so），
libkiwi 只做转发**。想解密文帧应查 `libapp.so`，不是 libkiwi。

Dart 侧出现过的算法线索：`chacha`×14、`aes`×33、`rabbit`×10、`salsa`×3、`cbc`×116、`ctr`×18。
（部分来自 pub 包，需结合 asm 才能定位真正链路。）

### 10.4 join 的 -5003：已排除的假设

| 假设 | 实测结果 |
|---|---|
| 正确路径是 `join_room_new` | ❌ 全部端口 404（REST 与明文 WS 通道一致） |
| 版本号传错 | ❌ `version_code`/`versionCode`/`app_version`/header 全试过 |
| 登录时登记版本过低 | ❌ 用真实版本 `20260226001` 重新 login，join 仍 -5003 |
| 房间属性（赌桌/收费） | ❌ 6 个房间含 5 个真人直播间，全 -5003 |
| 通道/鉴权问题 | ❌ `/room_push/leave` 成功、`change_pay_type` 能到业务层，仅 join 被拦 |

服务端版本接口实测（`POST /app_versions/get_new_version`）：
真实 `version_code=20260226001`、`version_name="最新"`、`is_force=0`（不强制更新）。

Dart 字符串池中**不存在** `請前往系統設定 > 更新版本` 这句文案 → 它是服务端下发、客户端纯透传，
所以"Dart 里找 -5003 处理逻辑"这条路本身不存在。
