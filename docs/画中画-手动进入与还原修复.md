# 画中画：改手动进入 + 修复「还原按钮点不到」

> 实测环境：MuMu / Android 15（emulator-5554，桌面 1600×900 横屏），debug 包 `com.duocai.live.debug`。

## 一、需求

1. 画中画只由用户手动开启，**回到桌面不自动弹小窗**。
2. 修掉小窗里「鼠标悬停出现遮罩 → 点还原/全屏按钮没反应」的问题。

## 二、实测现象

进入小窗后（`input tap` 点播放页顶栏「浮窗」）：

- PiP 窗口出现，`dumpsys window` 里能看到 `PipMenuView`、`pip_input_consumer`、`pip-dismiss-overlay`；
- 鼠标悬停时 SystemUI 在小窗上铺一层菜单：**左上齿轮（设置）、右上 X（关闭）、正中间方块箭头（全屏）**，整块区域被一层半透明遮罩盖住；
- 此时点面板上的按钮，`InputDispatcher` 记录事件被 `pip_input_consumer` 收走，但按钮经常没反应；
- 日志里 SystemUI 侧持续报：
  ```
  SurfaceFlinger: Out of order buffers detected for RequestedLayerState{PipMenuView#1078 ...}
  ```
  说明 Simulator/ROM 上 **PiP 菜单图层与应用图层的合成顺序不稳定**。

## 三、根因

### 3.1 自动进小窗

`MainActivity.onUserLeaveHint()` 里判断 `c.autoPip && openIndex >= 0` 就 `enterPip()`，
默认 `autoPip = true`，所以按 Home 会自动缩窗。

### 3.2 「还原」点不到，三件事叠在一起

1. **自绘按钮位置占了系统的坑**：原来放在 `Alignment.TopEnd`（右上角 6dp），
   正好压在系统菜单的「关闭 X」上。悬停时菜单浮上来，两层抢同一块命中区。
2. **小窗里还挂着两块全屏层**：
   - `PlayerGestureLayer(enabled = !inPip)` —— 虽然 disabled，但它是一块铺满全屏的
     `pointerInput` 节点，PiP 的输入又由 SystemUI 的 `pip_input_consumer` 统一接管，
     等于跟系统菜单抢同一次点击；
   - `CoverPage` —— 视频没 ready 时 `alpha=1`，整屏渐变封面；ready 时 `alpha=0` 但
     **仍会为这一层单独开离屏缓冲**（`graphicsLayer { alpha }`），在模拟器上和 PiP 菜单
     的合成顺序打架，观感就是「按钮上蒙了一层阴影」。

     **这一层就是「遮罩盖住系统按钮」的本体**：它是整屏不透明的一层，而模拟器上应用层
     的合成排在了 `PipMenuView` 之上（就是上面那条 `Out of order buffers`）。于是
     正中间的「全屏」键、左上角的「设置」齿轮全被它盖住，只剩我们自己画的「还原」
     （在 `Box` 里排在封面之后、同一层里更靠上）还看得见 —— 用户看到的就是
     「有一层遮罩，只挡系统按钮，不挡自己的按钮」。
3. **`exitPipToFull()` 走的是空操作**：原来只有
   `startActivity(REORDER_TO_FRONT)`。Activity 本来就在栈顶，这条等于什么都没做，
   系统仍认为在 PiP 里 → 表现为「点了没反应」。

## 四、改动

| 文件 | 改动 |
|---|---|
| `MainActivity.kt` | 删掉 `onUserLeaveHint()` 整段自动进小窗逻辑；`pipParams()` 增加 **`setSourceRectHint`**（居中 9:16 区域，进出小窗的过渡不再多出一圈黑边）；`onPictureInPictureModeChanged` 里的 `syncPip()` 改成 `decorView.post {}` **延后一帧**（避免跟系统的展开事务抢状态机）；`exitPipToFull()` 改为 **`moveTaskToFront` + `REORDER_TO_FRONT` 双保险**；新增 `onStop()`：不在 PiP 就暂停播放（不再后台偷跑流量/声音） |
| `AndroidManifest.xml` | 增加 `android.permission.REORDER_TASKS`（`moveTaskToFront` 需要） |
| `AppContainer.kt` | 删 `autoPip` 属性 |
| `Prefs.kt` | 删 `autoPip` / `K_AUTO_PIP` |
| `SettingsScreen.kt` | 删「切后台自动浮窗」开关，改为一行说明 |
| `PlayerScreen.kt` | 小窗里 **不挂手势层、不画封面**；视频层在小窗里固定 `alpha=1`（不淡入、不开离屏层）；「还原」按钮从右上角移到**底部居中**（系统菜单只用顶部，这块留给我们），并加文字「还原」 |

### 为什么按钮放底部

SystemUI 的 PiP 菜单是「顶部一条工具条 + 中间展开键」，底部是空的。
把还原入口放底部，物理上就不可能和系统按钮重叠 —— 这是这次最直接的修复。

## 五、验证点

1. 播放页点顶栏「浮窗」→ 进小窗；**按 Home 不再自动进小窗**。
2. 小窗里点底部「还原」→ 回到全屏，播放不断（不重建播放器）。
3. 鼠标悬停小窗 → 系统菜单出现时，底部「还原」依然可点。
4. 退到桌面（不进小窗）→ 声音停止；回到 App 继续播。
5. 设置页原来的「切后台自动浮窗」开关已消失。
