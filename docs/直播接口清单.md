## 0. 结论

| 项 | 状态 |
|---|---|
| 接口路径（~200 条） | **已拿全**，见附录 A |

## 1. 主链路（推荐顺序）

```text
0) (可选) 登录      POST /login/sms_vcode_create {mobile}
                    POST /login/mobile {mobile, code} -> token
                    POST /login/quick {deviceId}      -> 游客 token
1) 大厅列表         POST /room/list {pageIndex, menuId}
                    ⚠️ 8.5.3 已下线（所有端口 404）。替代：自带房间号池 + 第 2 步，
                       见 docs/8.5.3接口现状.md §3
                      -> ListReply.data(ListReplyData)
                         .result    = 房间 ID 列表 (packed int64)
                         .countList = 各房人数 (packed int64)
                         .resultData= 主播 UserData 列表
                         .hasNext   = 是否有下一页
2) 房间详情         POST /room/get_list_by_ids {ids:"123,456,…"}   ← 8.5.3 实际用的是这个
                      ->  {"code":0,"rooms":[Room…]}   （ids 是逗号串，空值回 code -1）
                    旧文档里写的 /room/get_info_by_ids 在 8.5.3 并不存在
3) 进房(可选)       WS /websock/join {room_id}
                      -> ResultData { room, joinKey } / video 推送 (含 playRtmp)
4) 拿流             Room/Video 里的 playRtmp / playFlv / playHls
                    实测：rtmp://<域名>/live/<房间号> 零鉴权即可拉
5) 播放             PotPlayer / ffplay / VLC 直接播
6) 退房             WS /websock/leave
```

## 2. 请求/响应封装（protobuf）

```text
POST {BASE_ORIGIN}{pathPrefix}/{base64url(混淆路径)}
# App 内部: serverUri(形如 https://api.xxx.com/go) + api_path
#           -> updateSocketParams 判定 path 以 /go 开头 -> 替换为 {prefix}/{base64url}
Headers:
  cipher:  base64(8B IV)          # RabbitCipher IV
  checksum: md5hex(明文 protobuf)
  Content-Type / Accept: application/proto
  Authorization: Bearer <jwt>
Body:
  bean.Request {
    1: random  (int,  自增计数器)
    2: time    (int,  unix 秒)
    3: path    (string, 如 "/room/list")
    4: data    (bytes,  业务 protobuf)
  }
  → 整体 RabbitCipher(key=MD5(SALT+hour+token), iv=cipher头) 加密

Response(JSON):
  { "code":0, "msg":"", "data": { "body": <加密 protobuf>, "cipher": <IV?>, "httpStatus": 0 } }
  bean.Response { 1:random, 2:body(bytes), 3:httpStatus }
```

## 4. protobuf schema（关键消息，字段号已核对）

```protobuf
// ---- 包装层 (bean) ----
message Request  { optional int32 random = 1; optional int64 time = 2;
                   optional string path = 3; optional bytes data = 4; }
message Response { optional int32 random = 1; optional bytes body = 2;
                   optional int32 httpStatus = 3; }

// ---- 房间 (room.v1) ----
message ListRequest      { optional int32 pageIndex = 1; optional int32 menuId = 2;
                           optional string params = 3; optional string channelId = 4; }
message ListReply        { optional Error error = 1; optional ListReplyData data = 2; }
message ListReplyData    { repeated int64 result = 1;      // 房间 ID
                           repeated int64 countList = 2;  // 各房人数
                           optional int32 hasNext = 3;
                           repeated UserData resultData = 5; }
message GetInfoByIdsRequest { repeated int64 ids = 1; }
message GetInfoByIdsReply   { optional Error error = 1; optional RoomInfoList data = 2; }
message RoomInfoList        { repeated Room list = 1; }
message JoinRoomV2Request   { optional int64 userId = 1; }
message JoinRoomV2Reply     { optional Error error = 1; optional ResultData data = 2; }
message ResultData          { optional int64 battleId = 1; optional Room room = 3;
                              optional string joinKey = 5; }

// ---- 实体 (types) ----
message Room  { optional int64 id = 1; optional string name = 2; optional int32 menuId = 3;
                optional string city = 4; optional string cityShow = 5; optional int32 sex = 6;
                optional int64 attachment = 7; optional int32 liveIn = 8;
                optional int32 livePayType = 9; optional int32 liveFee = 10;
                optional int32 hasGuangNian = 11; optional int32 onAir = 12;
                optional int64 chessId = 13; optional int64 battleId = 14;
                optional string attachmentUrl = 20; optional int32 playerCount = 21;
                optional int64 expiresTime = 22; optional int32 titleId = 23;
                optional string desc = 24; optional string pic = 25;   // 封面
                optional int32 flag = 26; optional int32 isVibratorOpen = 27;
                optional int32 streamFlag = 28; }
message Video { optional string pushRtmp = 8;  optional string playRtmp = 9;
                optional string playFlv = 10;  optional string playHls = 11;
                optional string liveImage = 12; optional string agoraChan = 24;
                optional int32 onAir = 28;     optional string title = 31; }
message UserData { optional string avatar = 2; optional string nickname = 3;
                   optional int32 sex = 4; optional int32 level = 5;
                   optional int32 vipLevel = 6; optional string signature = 8;
                   optional bool isPodcast = 9; optional int32 liveIn = 10; }
```

## 6. 拿 BASE 域名（唯一缺的一步，3 选 1）

### A. logcat（最快）
```bash
adb logcat -c && adb logcat | findstr /i "连接服务器 当前版本 过盾 host"
```
### B. Frida（最准，附带 dump 加密明文）
```bash
frida -U -f com.ufnhzkflua.eyybasftmi -l tools/frida_hook_crypto.js --no-pause
# 输出里的 [TCP] ip:port 与 updateSocketParams url= 即接口域名(形如 https://api.xxx.com/go)
```
### C. mitmproxy（要 headers/token 时）
手机同网段代理到电脑 `mitmproxy --listen-port 8080`，root 机装系统 CA；
抓 `POST /room/*`，把 `cipher`/`checksum`/`Authorization` 抄下来备用。

> 拿到后填 `webui/config.json` 的 `base`（**只要 origin，不带 `/go`**）和 `token`，或
> `set BASE=https://api.xxx.com` 后跑 `python tools/live_client.py rooms`。
> 最终 URL = `base + pathPrefix + "/" + base64url(加密路径)`，`pathPrefix` 默认 `/go`。

## 7. 注意

1. `checksum` 是**明文** protobuf 的 md5，不是密文的——别算错。
2. key 每小时轮换（SALT+hour+token），跨小时请求要用新 key。
3. RTC 房没有 RTMP 直链，只能声网 token 进频道。
4. 付费房 `playRtmp` 可能是预览流或带 `txTime` 短时效，过期需重新 join。
5. 接口会随版本变；服务端加签/加盾后需重新抓一次对齐 headers。

# 11. 直播间实时通道 `/websock/*`（2026-10-29 抓包坐实，已可独立复现）

这一节替换掉旧结论里「进房 `/room_push/join` 一直 -5003」那一段：**路径就是错的**，
8.5.3 的进房接口叫 `/websock/join`，`/room_push/join` 是更早版本的命名。

## 11.1 三个硬性前提（缺一个就失败，报错各不相同）

| 前提 | 值 / 来源 | 缺了会怎样 |
|---|---|---|
| 隧道 URL 的 `?token=` | **App 当前会话的 32 位 hex**（`.apptoken.txt`，实测 `e24bae48…`） | `{"code":-10000,"msg":"bad token, please login!"}` |
| `authorization: Bearer <JWE>` | `.jwe.txt`，App prefs 里 `token` 字段那个 330 字符 JWE | 同样 -10000 |
| 端口是同一台 vhost | 实测 **1406 / 37549** 同时支持 `/index/hello` 和 `/websock/*` | 404（`{"code":0}`）或 HTTP 403 |

> 坑：自己的 quick-login token 在这条路径上**不管用**，服务端只认 App 已登录会话的那个 32 位 hex。
> 拿法：`tcpdump -i lo -A` 抓 `GET /tunnel/open?...&token=`，或在 App 重启/切网时抓握手。
> 另外 `/websock/*` 走**普通 HTTP 一律 405**，必须走 WS 隧道。

## 11.2 接口

全部走 `/tunnel/open` 的「HTTP 代理」帧：
上行 `{"body":{…},"random":N,"method":"POST","uri":"<下面这些>"}`
下行 `{"opt":"http","data":{"status":200,"random":N,"body":"<转义 JSON>"}}`

⚠️ **`/websock/*` 的响应帧没有 `random` 字段**，只能按「发出去后的第一帧 http」对号入座。
之前 `collect()` 按 random 匹配，所以 join 一直拿到 `null`。

| uri | body | 返回 |
|---|---|---|
| `/websock/join` | `{"room_id":983379110,"menu_id":3,"cp_type":3}` | `{"code":0,"player_count":7564,"result":[<用户对象>…]}` |
| `/websock/history_msg` | `{"room_id":983379110,"start_id":0}` | `{"code":0,"result":[<消息对象>…]}` |
| `/websock/get_room_players_info` | `{"user_ids":"988477899,1943191551","room_id":983379110}` | `{"code":0,"result":[<用户对象>…]}` |
| `/websock/add_robot` | `{"menu_id":105,"user_id":423344474,"room_id":983379110}` | `{"code":0}` |
| `/websock/leave` | `{"room_id":983379110}` | `{"user_id":423344474,"room_id":983379110,"code":0}` |
| `/index/hello` | `{"app_version":"20260226001"}` | `{"code":0,"msg":"hello"}`（约 5s 一次心跳，`random` 自增） |

**`player_count` 就是在线人数** —— 这是之前一直缺的那个数字，`/room/get_list_by_ids` 里没有。

## 11.3 下行推送（`opt` 只有 `u` / `r` 两种）

`u` = 增量更新（单个对象），`r` = 批量（`data` 是 JSON 字符串，要二次 `json.loads`）。

| opt | ctl | data 形态 | 含义 |
|---|---|---|---|
| u | `room` | `{"id":<room>,"live_in":1,"live_fee":10,"live_pay_type":2}` | 房间状态：在线/收费/票价 |
| u | `room` | `{"id":<user>,"battle_id":<room>}` | 连麦（PK）开始 |
| u | `room` | `{"id":0,"battle_id":0}` | 连麦结束 |
| u | `room` | 完整用户对象 + `live_in`/`title_id`/`chess_id`/`city_show` | 有人**进场** |
| u | `video` | `{"id":<room>,"player_count":7564}` | 在线人数刷新 |
| r | `room_msg` | `[<消息对象>…]` | **弹幕 / 礼物 / 下注 / 管理操作** |
| r | `room_player` | `[<用户对象>…]` | 在场玩家批量刷新（榜单/麦序） |

## 11.4 消息对象与 `content_type` / `optcode`

```json
{"user_id":988477899,"room_id":983379110,"nickname":"杨总的迈巴赫",
 "content":"{\"text\":\"终于直播了么\",\"typ\":32}",
 "content_type":1,"optcode":32,"optcode_ref_id":1,
 "create_time":1793205668,"id":25494056623,"history":1}
```

| content_type | optcode | content 内容 | 显示为 |
|---|---|---|---|
| 1 | 32 | `{"text":"…","typ":32}` | 普通聊天弹幕 |
| 8 | 19 | `{"total_amount":20,"bet_list":["303-1-20"],"cp_game_string":"一分快三","cp_type":3,"draw_issue":"20261029030041","pp_user_id":…}` | **下注** |
| 8 | 20 | `{"pay_amount":39.2,"cp_name":"一分快三","broken_id":…}` | **结算/中奖** |
| 8 | 1 | `{"typed":0,"operator_id":…,"time_str":"永久"}` | 管理操作（禁言/踢人） |
| 8 | — | `{"podcast_id":…,"url":"app:…"}` | 礼物/动效跳转 |

`history`=1 表示是 `history_msg` 回放的历史消息，实时推送没有这个字段。

## 11.5 用户对象（join / get_room_players_info / room_player 通用）

```
id / nickname / avatar / level / vip_level / anchor_level / weight
room_id / device_type / channel_id("chunx"/"meiy"/"tui1"…)
user_item_str("100059,0,100134,0" 装扮/坐骑槽位) / car_id

```
