## 0. 一句话

本 App 只走**明文隧道**（`/tunnel/open` → 一个由 kiwi SDK 在本机起的 `127.0.0.1:<端口>` 反向代理），
不碰 `/go/` 加密 protobuf 通道。能用到的接口就这几类：**房间详情、关注、分类表、实时弹幕（WS）、播放（RTMP 直链）**。

三件事互不相干：**列表零凭证；关注只认 JWE；弹幕进房要「会话 token + JWE」，缺一个就是 403。**

## 1. 最新可用接口（8.5.3 实测 · 当前 App 在用）

### 1.1 凭证矩阵（三件事互不干扰）

| 能力 | 要什么 | 不要什么 | 备注 |
|---|---|---|---|
| 看列表 `get_list_by_ids` | 什么都不用 | token、JWE 都不需要 | 鉴权层之前就被路由走，裸奔 |
| **关注列表** `my_follow` | **JWE**（330 字符） | 与会话 token 无关 | 缺 JWE → `{"code":-1,"msg":"请先登录"}` |
| 弹幕进房 `/websock/join` | **会话 token(32hex) + JWE** | —— | 缺 token → `403 bad token`；JWE 也必带 |

> 完整推导、换号步骤、失效现象对照见 [凭证与换号.md](凭证与换号.md) 与 [弹幕专题.md](弹幕专题.md)。

### 1.2 房间 / 列表

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /room/get_list_by_ids` | ✅ 唯一批量房间接口 | `{"ids":"123,456"}` → `{"code":0,"rooms":[…]}`。**零凭证**（token/JWE 都不要）。`ids` 必须是**逗号分隔字符串**，传数组会静默返回 `rooms:[]`；空 ids 回 `{"code":-1,"msg":"ids is null"}`（不含 `rooms` 键，不能当端口探针）。 |
| `POST /login/get_data_by_tbname` | ✅ 配置/分类表 | `{"tb_name":"lobby_menu"}` → 34 条分类（真人区 5/101~105/108）。`{"tb_name":"item"/"vip"/"notice"}` 等静态表也可用；`{"tb_name":"room"}` 返回 `{"code":-2,"msg":"查询失败"}`（动态表不对外）。 |

- 分类表（`lobby_menu`）：一级 tab `1关注 / 2推荐 / 3热门 / 4附近`，二级分类 `5新人 / 8游戏 / 101星秀 / 102女神 / 103颜值 / 104交友 / 105音乐 / 108舞蹈`。
- 房间对象的 `menu_id` **只会是 8 / 101~105 / 108**，从来不是 1/2/3/4（那是大厅顶部 tab，不是房间属性）。
- 房间号来源：源 App 本地表 `localData:room.<uid>` 导出的种子池（`app/src/main/assets/room_ids.txt`，约 1972 个），App 只增不减。

### 1.3 关注

| 接口 | 状态 | 说明 |
|---|---|---|
| `POST /user_follow/my_follow` | ✅ | 关注列表。只认 `authorization: Bearer <JWE>`。`{}` 一次拿全（无分页），`result[].podcast_id` **就是房间号**（8/8 能命中 `/room/get_list_by_ids`，头像逐字节一致）。 |
| `POST /user_follow/add` | ⚠️ 写接口空转 | 本机明文隧道返回 `{"code":0}` 但**不落库**；读 `my_follow` 无变化。真正落库走源 App 内部 protobuf 隧道（`ProtobufHttpTunnelDelegate`），明文 HTTP 够不到。 |
| `POST /user_follow/cancel_follow` | ⚠️ 写接口空转 | 同上。 |

> App 的处理：写后**复查 `my_follow`** 是否真的变了作为成功判据；若没变则如实提示「服务端未确认」，
> 本地收藏兜底。即"代码路径正确（podcast_id + JWE + token），但本机明文写不进源 App 的库"。

### 1.4 实时通道（WS over `/tunnel/open`）

全部走 `/tunnel/open` 的「HTTP 代理」帧：
上行 `{"body":{…},"random":N,"method":"POST","uri":"<下面这些>"}`
下行 `{"opt":"http","data":{"status":200,"random":N,"body":"<转义 JSON>"}}`（`body` 是转义字符串，需二次解析）
`opt:"u" / "r"` 是服务端主动推送，不是对上行的应答。

| uri | 状态 | body | 返回 |
|---|---|---|---|
| `GET /tunnel/open` | ✅ | `?z=1&appversion=20260226001&token=<32hex>` | WS 升级（101）。必须带 `authorization: Bearer <JWE>`；`/websock/*` 走它，普通 HTTP 一律 405。 |
| `POST /login/init` | ✅ | `{}` | 启动数据（用户档案/钻石/公告/47KB 配置/背包），`opt:"u"/"r"` 一帧帧推下来。**仅支持长连接**，普通 HTTP 返回 `{"code":-2,"msg":"仅支持长连接"}`。 |
| `POST /websock/join` | ✅ | `{"room_id":983379110,"menu_id":3,"cp_type":3}` | `{"code":0,"player_count":7564,"result":[<用户>…]}`。**必须带 `?token=<32hex>` 会话 token**，缺则 `403 bad token`；`player_count` 就是在线人数。 |
| `POST /websock/history_msg` | ✅ | `{"room_id":983379110,"start_id":0}` | 历史弹幕 `{"code":0,"result":[<消息>…]}` |
| `POST /websock/get_room_players_info` | ✅ | `{"user_ids":"988477899,1943191551","room_id":983379110}` | 在场用户 `{"code":0,"result":[…]}` |
| `POST /websock/add_robot` | ✅ | `{"menu_id":105,"user_id":423344474,"room_id":983379110}` | `{"code":0}` |
| `POST /websock/leave` | ✅ | `{"room_id":983379110}` | `{"user_id":…,"room_id":…,"code":0}` |
| `POST /index/hello` | ✅ | `{"app_version":"20260226001"}` | `{"code":0,"msg":"hello"}`，约 5s 一次心跳，`random` 自增 |

**下行推送（`opt` 只有 `u` / `r` 两种）**：

| opt | ctl | data 形态 | 含义 |
|---|---|---|---|
| u | `room` | `{"id":<room>,"live_in":1,"live_fee":10,"live_pay_type":2}` | 房间状态：在线/收费/票价 |
| u | `room` | `{"id":<user>,"battle_id":<room>}` / `{"id":0,"battle_id":0}` | 连麦（PK）开始 / 结束 |
| u | `room` | 完整用户对象 + `live_in`/`title_id`/`chess_id`/`city_show` | 有人进场 |
| u | `video` | `{"id":<room>,"player_count":7564}` | 在线人数刷新 |
| r | `room_msg` | `[<消息对象>…]` | 弹幕 / 礼物 / 下注 / 管理操作 |
| r | `room_player` | `[<用户对象>…]` | 在场玩家批量刷新（榜单/麦序） |

> 消息对象与 `content_type`/`optcode` 见 [弹幕专题.md](弹幕专题.md)：普通弹幕 `content_type=1, optcode=32, content={"text":…,"typ":32}`；下注 `8/19`；结算 `8/20`；管理 `8/1`；礼物/动效 `8/-`。

### 1.5 播放（RTMP 零鉴权）

| 形态 | 状态 | 说明 |
|---|---|---|
| `rtmp://<域名>/live/<房间号>` | ✅ | 标准 RTMP，**服务端零鉴权**：`?token=…&t=…&liteavToken=…` 全去掉照样出流。域名平台级固定，抓一次长期复用（见 [视频流拉取方案.md](视频流拉取方案.md)）。 |
| `http://<域名>/live/<房间号>.flv` | ✅ | FLV 直链，同域名同鉴权策略。 |
| `.m3u8` | ⚠️ | 同台 nginx 实际回 FLV（没真做 HLS）。 |
| 封面图 `attachment_url` | ✅ | `/static/upload/...` → 换成 `https://drdue73ptt7o.cloudfront.net/images/<256\|480\|640\|1024>/...` 公网直连、零凭证、不经隧道（覆盖率 100%，随机抽测全 200）。 |

> 是否能拉流看房间属性：`chess_id == 3` 且 `menu_id >= 100` 才是可拉流的真人房；`chess_id=8`（百家乐/彩票桌）、`menu_id=8`（彩票频道）只有牌桌画面不走视频流。

### 1.7 端口与路由（token=身份，port=路由）

- **端口来源**：本机隧道端口由 App 内置 kiwi SDK 在启动时 `Init` 自起 listener（`libkiwi.so` + `kiwi-sdk.jar`），**装完即用，不依赖源 App**；SDK 失败（appKey 失效/非 arm64）才降级「借源 App 端口」（扫 `/proc/net/tcp` 的 LISTEN 端口）。
- **端口每次冷启动都变**（如 `38481 → 45209 → …`），App 自动扫描 + 失败重探，不写死。
- **端口判据不能是 `/room/list`**（已下线，全 404）。用真实房间号打 `/room/get_list_by_ids`，认 `rooms` 键的才是对的 vhost。
- **弹幕只能进 `kiwi_im` vhost**（imPort，如 38105/43991/38897/51547），其它 vhost 的 `/websock/*` 回 404；405 只说明「挂着 WS 路由」不算进房。
- **BASE 域名是占位符**：所有 `http://kiwi_*` 由 SDK 运行时替换成 `127.0.0.1:<端口>`（`kiwi_starts = "kiwi_,127.0.0.1"`），静态分析永远找不到真实域名。详见 [明文长连接通道.md](明文长连接通道.md)。

## 4. 旧版加密通道（/go/ protobuf）· 仅逆向参考，本 App 未使用

> 以下描述来自 8.1.7 的 `/go/` 加密路径还原，**当前 App 完全不走这条通道**（走的是 §1 的明文隧道）。
> 仅保留作为逆向背景；其中 `SALT`/`KEY_SALT` 在 8.5.3 已改成字节数组，`rabbit.py` 对 8.5.3 无效。

```text
POST {BASE_ORIGIN}{pathPrefix}/{base64url(混淆路径)}
# 混淆路径: base64Url(reverse(xor(reverse(xor(path,R1)),R2))+R2)
Headers:
  cipher:  base64(8B IV)          # RabbitCipher IV
  checksum: md5hex(明文 protobuf)
  Content-Type / Accept: application/proto
  Authorization: Bearer <jwt>
Body:
  bean.Request {
    1: random  (int,  自增计数器)
    2: time    (int,  unix 秒)
    3: path    (string, 如 "/room/list")
    4: data    (bytes,  业务 protobuf)
  }
  → 整体 RabbitCipher(key=MD5(SALT+hour+token), iv=cipher头) 加密
Response(JSON):
  { "code":0, "msg":"", "data": { "body": <加密 protobuf>, "cipher": <IV?>, "httpStatus": 0 } }
  bean.Response { 1:random, 2:body(bytes), 3:httpStatus }
```

注意：
1. `checksum` 是**明文** protobuf 的 md5，不是密文的——别算错。
2. key 每小时轮换（SALT+hour+token），跨小时请求要用新 key（8.5.3 起 SALT 已不再是 ASCII 串）。
3. RTC 房没有 RTMP 直链，只能声网 token 进频道。
4. 付费房 `playRtmp` 可能是预览流或带 `txTime` 短时效，过期需重新 join。
5. 接口/路径会随版本变；服务端加签/加盾后需重新抓一次对齐 headers。
