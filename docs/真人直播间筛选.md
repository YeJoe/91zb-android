# 真人直播间 vs 博彩盘口房：怎么正确区分

> 2026-10-29 修正。结论是：**不需要拉流，接口里本来就有分类字段**。
> 之前那份「靠拉流探测过滤」的做法是错的，下面说明为什么。

## 1. 根因：参数名写错，导致一直拿到默认列表

`/room/list` 的分类参数叫 **`menu_id`（下划线）**，不是 `menuId`（驼峰）。

服务端遇到不认识的字段**不报错，直接回退到默认列表**，而默认列表以 `menu_id=8`（游戏区）为主——
这就是「打开全是 XX快三 / XX百家乐」的原因。

```diff
- POST /room/list  {"pageIndex":1,"menuId":101}     # 被忽略，返回默认列表
+ POST /room/list  {"menu_id":101}                  # 正确，返回星秀分类
```

改正后，各分类返回的是**完全不同的房间集合**（不是同一批换个顺序）。

`depth=80` 这一组是博彩频道，做真人直播列表时整组不要。

## 3. 各分类的「盘口名占比」

抓 342 个房，按 `menu_id` 分组，统计房间名里带盘口词（快三/百家乐/回血/倍投/和值…）的比例：

| menu_id | 分类 | 房间数 | 盘口名占比 |
|---|---|---|---|
| 104 | 交友 | 59 | **1.7%** |
| 105 | 音乐 | 21 | 9.5% |
| 103 | 颜值 | 68 | 13.2% |
| 102 | 女神 | 62 | 19.4% |
| 101 | 星秀 | 62 | 25.8% |
| 108 | 舞蹈 | 36 | 36.1% |
| **8** | **游戏** | 34 | **85.3%** |

交友最干净，游戏区基本全是推广位。真人分类里剩下的那点盘口名，是主播自己把房间名起成
「XX百家乐」拉客，实际仍在出镜——所以按名字过滤只能当**降噪**，不能当**分类**。

## 4. 为什么不能靠拉流判断

拉流只能测**「此刻有没有在推流」**，测不了**「是不是真人」**。实测反例：

| 房间 | 名字 | 在线人数 | 拉流 |
|---|---|---|---|
| 167047514 | 性瘾🍼小野猫 | 177 | I/O error |
| 1662310139 | 极品静静 | 141 | I/O error |
| 1916430984 | 可爱的丽娜 | 40 | I/O error |
| 894566158 | 梨花诗☁️ | 5616 | I/O error |

前三个名字明显是真人主播，人气 40~177（正因为下播了才掉成这个数），拉流稳定失败。
它们不是假房，是**下播的房**。

反过来，`on_air=1` 的 342 个房里 109 个拉不到流 —— 说明 `on_air` 这个字段本身不可信。

### 性能对比

| 方式 | 耗时 | 时效 |
|---|---|---|
| 全量拉流探测（342 房 / 16 并发） | 60~90 秒 | 做完就开始过期 |
| 按 `menu_id` 分类（9 次请求） | 1.5 秒 | 实时 |
| 拉详情补全（18 批） | 13 秒 | 实时 |

## 5. 那些看着像「流状态」的字段，全是废的

| 字段 | 实测 | 结论 |
|---|---|---|
| `stream_flag` | 237 个有值的**全是 0**，105 个连 key 都没有 | 废弃字段 |
| `flag` | 同上，恒 0 | 无用 |
| `on_air` | 341/342 都是 1 | 无区分力 |
| `live_in` | 340/342 都是 1 | 无区分力 |
| `desc` / `pic` / `expires_time` | 全空 / 全 0 | 无用 |
| `new_chess_id` | 342 个全 0 | 无用 |

**没有任何字段标记「是不是真人」或「有没有流」。** 能用的只有 `menu_id`。

`chess_id` 是「房间当前挂的玩法」（3=快三、8=百家乐…），真人主播也挂快三，
不能当身份判据（`chess_id=3` 里 84% 能拉到流）。

`sex` 只有统计相关性：可拉流的房里 sex=2 占 92%，不可拉流的房里 sex=1 占 48%，
能当参考、不能当规则。

## 6. 现在的实现

```
tools/build_site3.py   按 menu_id 拉 7 个真人分类 → 详情 → site/data.js（300 房，13 秒）
                       其中 84 个房间名带盘口词的标 ad=1，页面默认隐藏
tools/gateway.py       RTMP → HLS 本地网关（-c copy 不转码），让浏览器能真播
site/index.html        分类 + 搜索 + 列表 + 播放器 + 弹幕
site/vendor/hls.min.js hls.js，Chrome/Edge 不支持原生 HLS，必须靠它
```

用法：

```bash
python tools/build_site3.py      # 刷新数据
python tools/gateway.py          # 起网关（同时托管页面）
# 浏览器打开 http://127.0.0.1:8899/
```

不启网关也能直接双击 `site/index.html`，列表/分类/搜索/弹幕都能用，只是播放区会提示启动网关。

## 7. 已知边界

- `/room/list` 每个分类**固定返回 50 条**，`has_next=1` 但所有分页参数（`pageIndex`/`page`/`pageIndex`/
  `offset`/`limit`/`cursor`/游标类）全部无效，传未知字段还会让整个 body 回退到默认列表。
  所以单分类最多 50 个房，7 个分类去重后 300 个。
- 房间接口没有封面字段（`pic` 恒空，`attachment_url` 是头像且图片域名 403），页面用
  名字首字 + 渐变色块代替。
- 播放依赖本地 `ffmpeg`。网关默认最多同时转 4 路，空闲 50 秒自动回收。
